# App Features

## Initial Feature Set

رفيق القرآن should support these features from the beginning of the product plan:

- Daily random ayah.
- Tafsir Al-Muyassar, with UI prepared for multiple tafsir or meaning levels.
- Quran reading and mushaf browsing.
- Quran recitation audio.
- Morning, evening, sleep, after-prayer, wake-up adhkar, and selected duas.
- Adhkar counters.
- Prayer times.
- Adhan notification at each prayer time using one short bundled adhan sound.
- 10-minute pre-prayer notification.
- Daily Quran reading reminders at fixed natural times.
- Daily reading goal.
- Streak tracking.
- Reflection notes.
- Favorites and bookmarks.
- Share ayah as image.
- Offline mode from the beginning.
- Optional login from the beginning.
- Firebase sync only when logged in.
- Guest mode as local-only.

## Reminder Behavior

Daily Quran reminders must not be reduced or disabled automatically if the user ignores them for many days.

## Later Or Conditional Features

Ayah by state or mood may be added only with manually selected ayahs chosen by the project owner.

AI must not choose ayahs for mood, state, advice, rulings, or religious guidance.

## Content Source Requirements

- Quran text, tafsir, and recitation data must come from Quran Foundation / Quran.com or another verified source approved by the project owner.
- Adhkar must be stored in local JSON from a trusted source with source metadata.
- Prayer times should use AlAdhan.
- Adhan audio should be bundled locally.
